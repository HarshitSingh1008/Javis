### LAW 1 — SELF-HEALING INTELLIGENCE (The Core Differentiator)
If the agent receives a task it cannot currently perform, it must NEVER fail silently, return a generic error, or give up. The agent must enter a **capability synthesis loop**:
1. Detect the exact nature of the gap (missing module, unimplemented operation, unavailable API)
2. Construct a precise meta-prompt describing what Python capability is needed
3. Call the LLM to synthesize a complete, tested Python tool implementation
4. Route the synthesized code through the multi-layer security sandbox (AST → subprocess → Docker)
5. If validation passes: persist the tool to disk, embed it in vector memory, hot-register it to the live tool registry
6. Retry the original task using the newly registered tool
7. If synthesis fails after 3 attempts: return a precise, actionable error explaining exactly what the agent tried and what would be needed for a human to fix it

This loop must complete within a single agent graph cycle. The user should see the agent "think out loud" about the gap, attempt synthesis, and succeed — all as a seamless, impressive experience.

**Why this is the billion-dollar insight:** Current agents are static. Their capabilities are frozen at the moment of deployment. NEXUS AI is the first agent that becomes more capable with every task it fails. Every failure is a capability investment that permanently enriches the agent for every future user session.

---

### LAW 2 — PARALLEL EXECUTION PIPELINE (The Performance Differentiator)
Every multi-step task must be decomposed into a Directed Acyclic Graph (DAG) where independent sub-tasks execute concurrently:

```
Task: "Open VSCode, install the Prettier extension, format all JS files in my project, commit, and push"
│
├── [SEQUENTIAL: UI requires ordering]
│   ├── Step 1: Focus VSCode window
│   ├── Step 2: Install Prettier extension (depends on Step 1)
│   └── Step 3: Run format command (depends on Step 2)
│
└── [PARALLEL: can run simultaneously while Step 1-3 run]
    ├── Step A: Enumerate all .js files in project directory
    └── Step B: Check current git branch and status
        └── Step 4: Stage formatted files (depends on Steps 3 + A + B)
            └── Step 5: Commit + Push (depends on Step 4)
```

The orchestrator must identify the critical path, maximize parallelism outside it, and emit real-time progress to the UI so users see each step completing as it happens.

**Critical constraint:** Any task involving GUI automation (clicking, typing, windowing) must remain sequential within that GUI context. Parallel execution is for I/O-bound tasks: file operations, web requests, memory queries, system metrics, etc.

---

### LAW 3 — ZERO-LATENCY UI (The Experience Differentiator)
The GUI thread is sacred. Nothing may block it. Ever.

Enforcement mechanisms:
- All agent inference runs in a dedicated `threading.Thread` with its own event loop
- All tool execution runs in `ThreadPoolExecutor` workers
- All memory operations run in a dedicated memory thread
- All audio (TTS synthesis, wake word detection) runs in daemon threads
- The UI thread does exactly one thing: consume from queues and update the canvas

The queue contract:
```
[Agent Thread] → output_queue → [UI Thread] → stream to conversation log
[Agent Thread] → log_queue → [UI Thread] → update activity panel
[Audio Thread] → audio_state_queue → [UI Thread] → animate waveform
[Agent Thread] → progress_queue → [UI Thread] → update DAG progress panel
[System Monitor Thread] → metrics_queue → [UI Thread] → update CPU/RAM bars
```

If any queue consumer takes more than 16ms (one 60fps frame), it is doing too much work. Break it into smaller queue messages.

---

### LAW 4 — STATEFUL CONTEXT CONTINUITY (The Retention Differentiator)
The agent must remember everything it has ever learned, permanently:

- **Episodic Memory**: Every completed task, its tools, duration, success/failure, and outcome summary → stored in ChromaDB
- **Semantic Memory**: Facts the agent extracts from conversations ("the user's project is at ~/dev/myapp", "user prefers dark mode", "user's Git remote is named 'upstream'") → stored as vector embeddings
- **Procedural Memory**: Synthesized tools → persisted as Python files and vector-embedded code
- **Workflow Memory**: Compiled macros → stored as versioned JSON files with usage counters
- **Preference Memory**: Explicit and inferred user preferences → stored in session_context.json with timestamps

On every session start, the top-5 most semantically similar memories to the current conversation context are injected into the system prompt. The agent greets returning users with: "Welcome back. Last session I helped you with X. You might want to know that Y has changed since then."

A user who returns after one month should feel the agent is a colleague who remembers them, not a blank-slate assistant starting from scratch.

### LAW 5 — PLUGIN EXTENSIBILITY (The Ecosystem Differentiator)
The plugin architecture is the commercial moat. Design it to be irresistible to developers:

Plugin contract (dead simple by design):
```python
# my_plugin.py — Drop in ~/.nexus_ai/plugins/
def register(registry: ToolRegistry) -> list[PluginMetadata]:
    """Called at boot and on hot-reload. Return metadata for each registered tool."""
    registry.register(my_tool_function)
    return [PluginMetadata(name="my_tool", version="1.0.0", author="Jane Dev")]
```

That's the entire API surface. One function. Any Python developer can write this. The marketplace implications are enormous: Slack integration plugin, JIRA plugin, GitHub plugin, Notion plugin, database query plugin — all installable with `nexus install <plugin-name>`.

Plugin system must support:
- Hot-reload without restart (watchdog-based file monitoring)
- Plugin dependency declaration (plugins can require other plugins)
- Plugin versioning and conflict detection
- Plugin sandboxing (plugin tools still route through SecureSandbox)
- Plugin marketplace manifest format (`plugin.toml` with name, description, version, author, tags, requirements)

### LAW 6 — OBSERVABILITY (The Enterprise Trust Differentiator)
Every action the agent takes must be observable, auditable, and explainable:

- **Audit Log**: Every tool call, agent step, capability synthesis, plugin load → JSON-lines log with ISO timestamps, session IDs, durations, and redacted payloads
- **Explainability**: The agent must be able to explain, in natural language, every decision it made during a task. "I chose to use browser_ghost instead of fetch_webpage because the site uses JavaScript rendering."
- **Metrics**: Tool call counts, success rates, average durations, synthesis counts, fallback trigger counts — all emitted to a local metrics file compatible with Prometheus scraping
- **Crash Forensics**: On unhandled exception: full stack trace, last 10 agent state snapshots, last 10 audit log entries, system metrics at time of crash → all written to a single crash report file
- **Health Checks**: A `nexus health` CLI command that validates all subsystems, reports API key status, ChromaDB connectivity, audio device availability, and last boot time

### LAW 7 — HARDWARE AGNOSTICISM (The Distribution Differentiator)
NEXUS AI must run on Windows 10/11, macOS 12+, and Ubuntu 20.04+ with zero code changes:

- No hardcoded paths (use `pathlib.Path`, `platform.system()`, and `os.sep` everywhere)
- No hardcoded Windows-only audio (`winsound` is banned — use `pygame.mixer`)
- No hardcoded macOS-only features
- No hardcoded Linux-only features
- Window management abstracted behind a unified API (`pygetwindow` on Windows, `wmctrl`/`python-xlib` on Linux, `AppKit`/`pyobjc` on macOS)
- Screen resolution and DPI-aware coordinate normalization for `pyautogui`
- All platform-specific branches clearly labeled with `# PLATFORM: Windows/macOS/Linux` comments

---

### LAW 8 — SECURITY-FIRST (The Enterprise Sales Differentiator)
Security is not an afterthought. It is designed in from the first line:

- **No `exec()` anywhere in production code** (only in the sandbox, heavily wrapped)
- **No API keys in source code** (all via `.env` with a first-boot entry dialog)
- **No plaintext sensitive data in logs** (the `auto_redact()` decorator is applied at the boundary)
- **AST static analysis before any dynamic code execution**
- **Subprocess isolation with resource limits**
- **Optional Docker container isolation for maximum security**
- **Input validation on every tool** (path traversal prevention, command injection prevention)
- **Rate limiting on LLM calls** (prevent runaway loops from burning API credits)
- **Capability firewall**: The agent can only perform actions in its tool registry. It cannot execute arbitrary code outside the `python_interpreter` tool's sandbox path.

---

### LAW 9 — GRACEFUL DEGRADATION (The Reliability Differentiator)
Every subsystem must have a graceful failure mode:

| Subsystem | Primary | Degraded Mode |
|---|---|---|
| LLM | Groq (llama-3.3-70b-versatile) | OpenAI GPT-4o → Local Ollama (llama3.2) |
| TTS | edge-tts + pygame | Print to console with `[NEXUS]:` prefix |
| Wake Word | pvporcupine | Keyboard shortcut (Ctrl+Shift+N) |
| Audio Playback | pygame.mixer | Silent (continue without sound) |
| ChromaDB | Persistent local | In-memory fallback (warn user) |
| Sandbox | Docker (preferred) | Subprocess → AST-only (reject execution) |
| Plugin | Any plugin | Skip with warning, continue boot |

The system must never crash due to a missing audio device, unavailable microphone, or Docker absence. These are features, not requirements.

---

### LAW 10 — LLM TOKEN EFFICIENCY (The Cost Differentiator)
Every LLM call must be designed to minimize token consumption without losing effectiveness:

- System prompts are pre-computed once at boot, not reconstructed per call
- Conversation context is pruned using semantic similarity: only the N most relevant prior messages are included, not the full history
- Tool descriptions in the LangChain registry are concise but precise (under 150 words each)
- The task planner uses a separate, cheaper LLM call with a tight schema-constrained prompt to decompose tasks (not the full reasoning model)
- Capability synthesis uses a structured output prompt that forces the LLM to return only valid JSON (no prose padding)
- Memory injection is limited to 500 tokens of context (the 5 most relevant memories, summarized)

```python
def audited(event_type: str, module: str = None):
```

```python
class SecurityVisitor(ast.NodeVisitor):
    def __init__(self):
        self.violations: List[str] = []
    
    def visit_Import(self, node):
        for alias in node.names:
            module_root = alias.name.split(".")[0]
            if module_root in BANNED_IMPORTS:
                self.violations.append(f"Line {node.lineno}: Banned import '{alias.name}'")
            elif module_root not in WHITELISTED_IMPORTS:
                self.violations.append(f"Line {node.lineno}: Unlisted import '{alias.name}' (not in whitelist)")
        self.generic_visit(node)
    
    def visit_ImportFrom(self, node):
        # Same logic for 'from X import Y' patterns
        ...
    
    def visit_Attribute(self, node):
        if isinstance(node.attr, str) and node.attr in BANNED_ATTRIBUTES:
            self.violations.append(f"Line {node.lineno}: Banned attribute access '.{node.attr}'")
        self.generic_visit(node)
    
    def visit_Call(self, node):
        # Detect eval(), exec(), __import__() as direct calls
        if isinstance(node.func, ast.Name) and node.func.id in {"eval", "exec", "__import__", "compile"}:
            self.violations.append(f"Line {node.lineno}: Banned function call '{node.func.id}()'")
        self.generic_visit(node)
    
    def visit_Constant(self, node):
        # Detect string-based code execution patterns
        # (e.g., compile("os.system(...)", ...))
        # Only flag if the constant is a string AND is the direct arg to a banned call
        # This is checked in visit_Call instead
```

```python
def _execute_subprocess(self, code: str, timeout: int) -> SandboxResult:
    """
    Execute code in a clean subprocess with resource limits.
    """
    # Write to temp file (safer than -c for long code)
    temp_script = APP_ROOT / "temp" / f"sandbox_{uuid.uuid4().hex}.py"
    temp_script.write_text(code, encoding="utf-8")
    
    env = {
        "PYTHONPATH": "",  # Strip all custom paths
        "PATH": "/usr/bin:/bin" if is_linux() else os.environ.get("PATH", ""),
        "HOME": str(Path.home()),  # Minimal environment
    }
    
    preexec = None
    if is_linux() or is_macos():
        def preexec():
            import resource
            resource.setrlimit(resource.RLIMIT_AS, 
                (settings.SANDBOX_MAX_MEMORY_MB * 1024 * 1024,) * 2)
            resource.setrlimit(resource.RLIMIT_CPU, 
                (settings.SANDBOX_MAX_CPU_SECONDS,) * 2)
            resource.setrlimit(resource.RLIMIT_NPROC, (10, 10))  # No forking
    
    try:
        process = subprocess.Popen(
            [sys.executable, "-I", "-s", str(temp_script)],
            # -I: isolated mode (ignores PYTHON* env vars, user site-packages)
            # -s: don't add user site-packages to sys.path
            stdout=subprocess.PIPE,
            stderr=subprocess.PIPE,
            env=env,
            preexec_fn=preexec if (is_linux() or is_macos()) else None,
            creationflags=subprocess.CREATE_NEW_PROCESS_GROUP if is_windows() else 0,
        )
        stdout, stderr = process.communicate(timeout=timeout)
        ...
    finally:
        temp_script.unlink(missing_ok=True)
```

```python
async def synthesize_and_register(
    self, 
    task_description: str, 
    failure_reason: str,
    llm_router: "LLMRouter"
) -> SynthesisResult:
    
    # STEP 1: Gap analysis — what capability is actually needed?
    gap_analysis = await self._analyze_gap(task_description, failure_reason, llm_router)
    
    synthesis_start = time.perf_counter()
    
    for attempt in range(1, settings.SYNTHESIS_MAX_RETRIES + 1):
        # STEP 2: Synthesize the tool code
        raw_json = await self._call_synthesis_llm(
            SynthesisRequest(
                task_description=task_description,
                failure_reason=failure_reason,
                missing_capability=gap_analysis,
                current_tools=self.registry.get_all_tool_names(),
                attempt_number=attempt,
                previous_violations=violations_so_far,
            ),
            llm_router
        )
        
        # STEP 3: Parse and validate the JSON response
        try:
            synthesis_data = json.loads(raw_json)
            tool_code = synthesis_data["code"]
            tool_name = synthesis_data["tool_name"]
        except (json.JSONDecodeError, KeyError) as e:
            violations_so_far.append(f"Invalid JSON response: {e}")
            continue
        
        # STEP 4: AST security validation (dry run — no execution yet)
        ast_result = self.sandbox.validate_ast_only(tool_code)
        if not ast_result.success:
            violations_so_far.extend(ast_result.violations)
            audit_logger.log(event_type="SYNTHESIS_RETRY", data={"violations": ast_result.violations})
            continue
        
        # STEP 5: Functional test — run the code with a minimal test call
        test_result = self.sandbox.execute(
            code=tool_code + f"\n\nresult = {tool_name}.__doc__\nprint(result)",
            timeout=10  # Short timeout for test run
        )
        if not test_result.success:
            violations_so_far.append(f"Execution test failed: {test_result.stderr}")
            continue
        
        # STEP 6: Persist to disk
        tool_path = APP_ROOT / "synthesized_tools" / f"{tool_name}.py"
        tool_path.write_text(tool_code, encoding="utf-8")
        
        # STEP 7: Store in vector memory
        self.vector_store.store(
            text=f"{synthesis_data['tool_name']}: {synthesis_data['description']}. Code: {tool_code[:500]}",
            metadata={
                "tool_name": tool_name,
                "task_that_triggered": task_description,
                "created_at": datetime.now(timezone.utc).isoformat(),
                "attempt_number": attempt,
            },
            collection="synthesized_tools"
        )
        
        # STEP 8: Hot-register via importlib
        tool_fn = self._import_and_extract_tool(tool_path, tool_name)
        self.registry.register_runtime_tool(tool_fn)
        
        # STEP 9: Update session context
        self.session_context.synthesized_tool_names.append(tool_name)
        self.session_context.total_synthesis_events += 1
        
        registration_time = (time.perf_counter() - synthesis_start) * 1000
        
        audit_logger.log(
            event_type="CAPABILITY_SYNTH",
            data={
                "tool_name": tool_name,
                "task": task_description,
                "attempt": attempt,
                "success": True,
            }
        )
        
        return SynthesisResult(
            success=True,
            tool_name=tool_name,
            tool_description=synthesis_data["description"],
            code=tool_code,
            retry_count=attempt,
            validation_errors=[],
            registration_time_ms=registration_time,
            synthesis_time_ms=(time.perf_counter() - synthesis_start) * 1000,
        )
    
    # All retries exhausted
    return SynthesisResult(success=False, ...)
```

```python
class PluginReloadHandler(FileSystemEventHandler):
    def __init__(self, registry: ToolRegistry):
        self.registry = registry
        self._debounce_timer: Dict[str, threading.Timer] = {}
    
    def on_modified(self, event: FileModifiedEvent):
        if not event.src_path.endswith(".py"):
            return
        # Debounce: wait for PLUGIN_RELOAD_DEBOUNCE_SECONDS before reloading
        # (editors save files in multiple rapid writes)
        path = Path(event.src_path)
        if path in self._debounce_timer:
            self._debounce_timer[path].cancel()
        timer = threading.Timer(
            settings.PLUGIN_RELOAD_DEBOUNCE_SECONDS,
            self.registry.hot_reload_plugin, args=[path]
        )
        self._debounce_timer[path] = timer
        timer.start()
```

```python
    # Add edges
    graph.add_edge("memory_read", "complexity_check")
    
    graph.add_conditional_edges("complexity_check", self._route_by_complexity, {
        "simple": "agent",
        "complex": "planner",
        "ui_automation": "agent",
    })
    
    graph.add_edge("planner", "agent")
    
    graph.add_conditional_edges("agent", self._route_after_agent, {
        "tools": "tools",
        "end": "memory_write",
    })
    
    graph.add_conditional_edges("tools", self._route_after_tools, {
        "agent": "agent",
        "capability_check": "capability_check",
    })
    
    graph.add_conditional_edges("capability_check", self._route_after_capability_check, {
        "synthesizer": "synthesizer",
        "agent": "agent",  # Non-synthesis failure, let agent handle
    })
    
    graph.add_edge("synthesizer", "tools")  # Retry after synthesis
    graph.add_edge("memory_write", END)
    
    return graph.compile(checkpointer=MemorySaver())
```

```python
async def execute_dag(
    self,
    dag: TaskDAG,
    tool_registry: ToolRegistry,
    progress_queue: asyncio.Queue,
) -> DAGResult:
    """
    Execute a TaskDAG with maximum parallelism.
    
    Algorithm:
    1. Build a dependency graph
    2. Find all nodes with no unfulfilled dependencies (ready_nodes)
    3. Submit all ready_nodes to asyncio tasks concurrently
    4. As tasks complete, add newly-unblocked nodes to ready_nodes
    5. Serialize any nodes where is_ui_automation=True
    6. Collect all results; handle failures per can_fail_safely flag
    """
    semaphore = asyncio.Semaphore(settings.PARALLEL_TOOL_WORKERS)
    completed: Dict[str, Any] = {}
    failed: List[str] = []
    
    async def execute_node(node: TaskNode):
        async with semaphore:
            await progress_queue.put(ProgressEvent(node_id=node.id, status="started"))
            try:
                tool = tool_registry.get_tool(node.suggested_tool)
                result = await asyncio.to_thread(tool.invoke, node.tool_args)
                completed[node.id] = result
                await progress_queue.put(ProgressEvent(node_id=node.id, status="completed"))
            except Exception as e:
                failed.append(node.id)
                if not node.can_fail_safely:
                    raise
    
    # Topological execution with asyncio
    pending = {node.id: asyncio.create_task(execute_node(node)) 
               for node in dag.nodes 
               if not node.depends_on}
    
    while pending:
        done, _ = await asyncio.wait(pending.values(), return_when=asyncio.FIRST_COMPLETED)
        for task in done:
            completed_id = ...
            del pending[completed_id]
            # Add newly-unblocked nodes
            for node in dag.nodes:
                if (node.id not in completed and 
                    node.id not in pending and
                    all(dep in completed for dep in node.depends_on)):
                    pending[node.id] = asyncio.create_task(execute_node(node))
    
    return DAGResult(...)
```

```python
class Particle:
    def __init__(self, canvas_width: int, canvas_height: int):
        self.x = random.uniform(0, canvas_width)
        self.y = random.uniform(0, canvas_height)
        self.vx = random.uniform(-0.3, 0.3)  # Slow drift
        self.vy = random.uniform(-0.3, 0.3)
        self.size = random.uniform(1.0, 3.5)
        self.opacity = random.uniform(0.1, 0.6)  # As hex: 1A to 99
        self.pulse_phase = random.uniform(0, 2 * math.pi)  # Individual pulse offset
        self.color_variant = random.choice(["#00d4ff", "#7c3aed", "#00ff9d"])
    
    def update(self, mouse_x: float, mouse_y: float, dt: float):
        """
        Update position with:
        1. Drift: add velocity to position
        2. Mouse repulsion: if within 80px of cursor, apply inverse-square repulsion
        3. Boundary wrapping: wrap at canvas edges (not bounce)
        4. Velocity damping: slowly return to original drift speed
        5. Opacity pulse: individual sine wave oscillation
        """
        # Mouse repulsion
        dist = math.hypot(self.x - mouse_x, self.y - mouse_y)
        if dist < 80 and dist > 0:
            force = min(2.0, 80.0 / (dist * dist) * 0.5)
            self.vx += force * (self.x - mouse_x) / dist
            self.vy += force * (self.y - mouse_y) / dist
        
        # Damping
        self.vx *= 0.98
        self.vy *= 0.98
        
        self.x += self.vx
        self.y += self.vy
        
        # Wrap
        self.x %= canvas_width
        self.y %= canvas_height
        
        # Pulse
        self.pulse_phase += 0.02
        self.opacity = 0.2 + 0.4 * (0.5 + 0.5 * math.sin(self.pulse_phase))
```

```python
def _nexus_exception_hook(exc_type, exc_value, exc_traceback):
    """
    Catches ALL uncaught exceptions.
    1. Writes crash report to APP_ROOT/crash_reports/crash_{timestamp}.json
    2. Attempts to show tkinter error dialog
    3. Exits cleanly (code 1)
    """
    import traceback, json
    from datetime import datetime
    from pathlib import Path
    
    crash_time = datetime.now().strftime("%Y%m%d_%H%M%S")
    crash_path = Path.home() / ".nexus_ai" / "crash_reports" / f"crash_{crash_time}.json"
    
    crash_data = {
        "timestamp": datetime.now().isoformat(),
        "exception_type": str(exc_type.__name__),
        "exception_message": str(exc_value),
        "traceback": traceback.format_tb(exc_traceback),
        "python_version": sys.version,
        "platform": platform.platform(),
    }
    
    try:
        crash_path.parent.mkdir(parents=True, exist_ok=True)
        crash_path.write_text(json.dumps(crash_data, indent=2))
    except Exception:
        pass  # Best-effort crash write
    
    try:
        import tkinter.messagebox as mb
        mb.showerror("NEXUS AI — Critical Error", 
                     f"An unexpected error occurred:\n{exc_type.__name__}: {exc_value}\n\n"
                     f"Crash report: {crash_path}")
    except Exception:
        print(f"FATAL: {exc_type.__name__}: {exc_value}", file=sys.stderr)
    
    sys.exit(1)

sys.excepthook = _nexus_exception_hook


def main():
    """
    NEXUS AI boot sequence.
    
    CRITICAL BOOT ORDER — do not change:
    Steps 1-7 are FATAL (failure = exit with crash screen)
    Steps 8-10 are NON-FATAL (failure = continue with degraded capability)
    Step 11 is the main UI loop (blocks until window close)
    """
    from nexus_ui.custom_hud import NexusHUD
    
    # Initialize queues that connect all subsystems
    input_queue   = queue.Queue()       # User → Orchestrator
    output_queue  = queue.Queue()       # Orchestrator → UI (agent tokens)
    log_queue     = queue.Queue()       # All modules → UI (log events)
    progress_queue = queue.Queue()      # TaskPlanner → UI (DAG progress)
    audio_state_queue = queue.Queue()   # Audio → UI (waveform state)
    metrics_queue = queue.Queue()       # SystemMonitor → UI (CPU/RAM)
    
    boot_logger = logging.getLogger("nexus.boot")
    
    # ─── FATAL STEPS ────────────────────────────────────────────────
    
    try:
        # Step 1: Settings
        log_queue.put({"type": "boot", "step": 1, "message": "Loading configuration..."})
        from nexus_config.settings import get_settings, validate_on_boot
        settings = get_settings()
        boot_status = validate_on_boot()
        for w in boot_status.warnings:
            boot_logger.warning(w)
    except Exception as e:
        raise RuntimeError(f"Boot Step 1 (Settings) failed: {e}") from e
    
    try:
        # Step 2: Audit Logger
        log_queue.put({"type": "boot", "step": 2, "message": "Initializing audit logger..."})
        from nexus_config.audit_logger import get_audit_logger
        audit_logger = get_audit_logger()
        audit_logger.log(event_type="BOOT", data={"step": 2, "message": "Audit logger ready"})
    except Exception as e:
        raise RuntimeError(f"Boot Step 2 (Audit Logger) failed: {e}") from e
    
    # ... Steps 3-7 follow the same pattern ...
    
    # ─── NON-FATAL STEPS ────────────────────────────────────────────
    
    tts_engine = None
    try:
        # Step 8: TTS Engine
        from nexus_audio.tts_engine import TTSEngine
        tts_engine = TTSEngine(settings)
        tts_engine.play_sound("boot_chime")
    except Exception as e:
        boot_logger.warning(f"TTS Engine failed to initialize: {e}. Continuing without audio.")
    
    wake_word_daemon = None
    try:
        # Step 9: Wake Word Daemon
        from nexus_audio.wake_word import WakeWordDaemon
        wake_word_daemon = WakeWordDaemon(input_queue, log_queue, audio_state_queue)
        wake_word_daemon.start()
    except Exception as e:
        boot_logger.warning(f"Wake Word Daemon failed: {e}. Use keyboard input only.")
    
    # Start system metrics thread
    metrics_thread = threading.Thread(
        target=_metrics_loop,
        args=(metrics_queue,),
        daemon=True,
        name="nexus-metrics"
    )
    metrics_thread.start()
    
    # ─── MAIN UI LOOP ────────────────────────────────────────────────
    
    # Step 10: Launch HUD (blocks here until window is closed)
    hud = NexusHUD(
        input_queue=input_queue,
        output_queue=output_queue,
        log_queue=log_queue,
        progress_queue=progress_queue,
        audio_state_queue=audio_state_queue,
        metrics_queue=metrics_queue,
        orchestrator=orchestrator,
        settings=settings,
        boot_status=boot_status,
    )
    hud.run()  # Blocking call
    
    # ─── SHUTDOWN ────────────────────────────────────────────────────
    _shutdown(wake_word_daemon, tts_engine, orchestrator, session_context, audit_logger)


def _shutdown(wake_word_daemon, tts_engine, orchestrator, session_context, audit_logger):
    """
    Ordered shutdown sequence:
    1. Signal orchestrator to stop accepting new tasks
    2. Stop wake word daemon (join with 3s timeout)
    3. Play shutdown sound (synchronously — wait for completion)
    4. Flush and close audit logger
    5. Save session context
    6. Join remaining daemon threads
    """
    try:
        if wake_word_daemon: wake_word_daemon.stop()
        if tts_engine: tts_engine.play_sound("shutdown"); time.sleep(1.5)
        if session_context: session_context._save_sync()
        audit_logger.log(event_type="SHUTDOWN", data={"clean": True})
    except Exception as e:
        boot_logger.error(f"Error during shutdown: {e}")


if __name__ == "__main__":
    main()
```

## SECTION 11: COMMERCIAL DIFFERENTIATION & MOAT
## ═══════════════════════════════════════════════════════

The following features constitute the product's defensible competitive moat. They must be preserved, documented, and made more prominent in every refactor:

### Feature 1: Self-Healing Capability Synthesis
**Why it's a moat:** No desktop agent framework does this natively. AutoGPT doesn't. Copilot doesn't. The agent literally writes its own code and becomes permanently more capable. This is the "compound interest" of AI agents — each failure makes the product better for all future users.
**Marketing angle:** "NEXUS AI gets smarter every time it can't do something."

### Feature 2: Permanent Capability Accumulation
**Why it's a moat:** Traditional software has fixed capabilities at shipping time. NEXUS AI's capabilities grow with each session. After one month of use, a NEXUS AI install has 20-30 synthesized tools unique to that user's workflow. This creates powerful switching costs.
**Marketing angle:** "The longer you use it, the smarter it gets. Your AI, personalized."

### Feature 3: DAG-Parallel Task Execution
**Why it's a moat:** Every other LangChain/LangGraph agent executes tools sequentially. NEXUS AI's task planner identifies independent sub-tasks and runs them concurrently. A 5-step automation that takes 45 seconds sequentially takes 12 seconds in parallel.
**Marketing angle:** "3-5x faster than any other desktop agent."

### Feature 4: Plugin Developer Ecosystem
**Why it's a moat:** An open plugin ecosystem creates network effects. Every new plugin makes the product more valuable for all users. Plugin developers become evangelists. The plugin marketplace creates a revenue stream independent of API usage.
**Marketing angle:** "One API. Infinite possibilities. Build once, earn forever."

### Feature 5: Workflow Macro Compiler
**Why it's a moat:** Users can describe a workflow in plain English and get a reusable, shareable automation script. These become personal assets. The more workflows a user compiles, the more locked-in they are — in a good way.
**Marketing angle:** "Describe it once. Automate it forever."

### Feature 6: Zero-Crash Audio Degradation
**Why it's a moat:** Enterprise deployments often run on headless servers or VMs without audio devices. NEXUS AI runs identically in both environments. This is a hard requirement for enterprise sales.
**Marketing angle:** "Runs everywhere. Servers, workstations, VMs, containers."

### Feature 7: Triple LLM Fallback
**Why it's a moat:** No single LLM provider is 100% reliable. Groq has rate limits. OpenAI has outages. NEXUS AI has no single point of LLM failure. It can even run fully offline with Ollama.
**Marketing angle:** "Always on. No matter what."

### Feature 8: Enterprise Audit Trail
**Why it's a moat:** Every tool call, agent decision, and capability synthesis is logged in a structured, searchable, rotation-managed JSON-lines audit log. This is table-stakes for enterprise sales (SOC2, GDPR compliance).
**Marketing angle:** "Complete visibility. Every action, every decision, forever."

### Feature 9: Agent-Written Workflows (Meta-Automation)
**Why it's a moat (future roadmap):** The agent can observe its own repeated action patterns and automatically propose: "I notice you run this sequence every morning. Want me to compile it into a workflow?" This meta-automation layer doesn't exist anywhere else.
**Marketing angle:** "NEXUS AI watches how you work, then automates it for you."

```python
    failure_reason: str,

    Synthesize a new Python tool to fill a capability gap and register it live.
    
    This is the self-healing engine. It detects what capability is missing,
    generates a LangChain @tool implementation, validates it through the
    security sandbox, persists it to disk, embeds it in vector memory,

            - tool_description: One-sentence description of what the tool does
            - code: The complete synthesized Python code
            - retry_count: How many attempts were needed (1-3)
            - validation_errors: List of AST/security violations from failed attempts

        ...     failure_reason="ModuleNotFoundError: No module named 'pypdf2'",
        ...     llm_router=router,
        ... )
```

### Thread Safety
```python
# REQUIRED: Any data structure accessed from multiple threads must use proper synchronization.

# GOOD:
class ToolRegistry:
    def __init__(self):
        self._tools: Dict[str, BaseTool] = {}
        self._lock = threading.RLock()  # RLock for reentrant safety during hot-reload
    
    def register(self, tool_fn: BaseTool) -> None:
        with self._lock:
            self._tools[tool_fn.name] = tool_fn
    
    def get_all_tools(self) -> List[BaseTool]:
        with self._lock:
            return list(self._tools.values())  # Snapshot under lock

# BAD:
class ToolRegistry:
    def register(self, tool_fn):
        self._tools[tool_fn.name] = tool_fn  # Race condition on hot-reload
```
