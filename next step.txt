### 1.3 — Third-Party License Compliance (an automated pipeline step, not a one-time read)

Do not hand-write a NOTICES file from memory of what each library's license says — licenses
change between versions, and a manually maintained file silently rots.

**LAW L1 — SBOM ON EVERY BUILD.** Wire `pip-licenses --format=json` (or `cyclonedx-py`) into
the CI pipeline — `.github/workflows/security-scan.yml` already exists from v4.0, extend it —
to regenerate `THIRD_PARTY_NOTICES.md` on every release tag. Fail the build if a new dependency
introduces a copyleft license (GPL, AGPL) that hasn't been explicitly reviewed. LGPL and
permissive licenses (MIT, BSD, Apache-2.0) pass automatically.

**Two gotchas already inside the v4.0 dependency list, flagged now because they affect the
business model, not just the NOTICES file:**

1. **`pvporcupine` (wake word) is commercial software, not free-and-clear OSS.** Picovoice
   ships an SDK with some open components, but the runtime requires an AccessKey and is
   metered — free-tier usage is capped and still requires periodic online activation against
   Picovoice's servers, and real commercial deployment is a sales-negotiated paid plan. Two
   consequences for this architecture:
   - Budget a Picovoice line item once free-tier usage caps are exceeded — this is a real
     cost-of-goods line, not a one-time engineering cost. Confirm current pricing with
     Picovoice sales directly rather than assuming a fixed number.
   - **The online-activation requirement directly conflicts with the Enterprise tier's
     "air-gapped, no internet required" promise from the v4.0 prompt's Tier 4.** Resolve this
     explicitly — don't ship a feature that silently phones home in a product marketed as
     air-gapped. Two acceptable resolutions:
     - (a) Enterprise/air-gapped builds ship with wake word disabled, falling back to the
       existing `Ctrl+Shift+N` hotkey (this already matches the Degradation Matrix in LAW 9
       of the v4.0 prompt — no new code needed, just a build flag).
     - (b) Negotiate an offline/on-prem licensing exception with Picovoice specifically for
       Enterprise contracts before promising it to a customer.

2. **`pygame` is LGPL-2.1.** You can bundle it in a closed-source, paid desktop app — but LGPL
   requires that a user be able to replace the LGPL component with a modified version of their
   own. For a PyInstaller-frozen executable this typically means dynamic linking rather than
   baking pygame into a single-file exe in a way that prevents replacement. This is a genuinely
   fiddly area of packaging plus license law — get a few minutes of a lawyer's time on your
   specific PyInstaller/Nuitka build config before the first paid sale rather than guessing.

### 1.5 — Operating From India: Tax & Entity Notes

*(Not tax advice — get a chartered accountant. These are the shapes of the two paths, not
instructions to follow directly.)*

Revenue from foreign subscribers is **export of services** under Indian GST law, generally
eligible for zero-rating if you file a **Letter of Undertaking (LUT)** — meaning no 18% GST
on export invoices — but the exact current forms and portal process should be confirmed
directly with a CA rather than from this document, since procedure details shift. Income is
still taxable under income tax law regardless of GST treatment. Sole proprietorship vs. a
private limited company changes liability exposure and is worth one paid consultation before
your first real subscriber.

**Payment collection reality check, as of mid-2026** — worth knowing before picking an
architecture, since it changes which webhook integration to build first:

- Stripe's direct India onboarding has been invite-only since May 2024 and remains restricted
  in 2026. It's usable if you get an invite, but it's card-only, doesn't auto-generate the
  FIRC/eFIRC documentation Indian exporters need for GST/FEMA records, and the effective cost
  after conversion and GST-on-fees runs around 6% for cross-border transactions.
- **Merchant of Record (MoR) platforms** — Paddle, Lemon Squeezy, Dodo Payments, Creem — sell
  the product on your behalf, appear as the seller on the customer's statement, and handle
  VAT/GST/sales-tax collection and remittance in every jurisdiction for you, for a higher fee
  (typically 4-5% + a flat fee per transaction, vs. roughly 2.9%+30¢ for a plain processor).
  For a solo developer with no in-house finance function, that fee premium is usually a
  reasonable trade for not personally owing sales-tax filings in dozens of countries.
- If you'd rather bill directly and keep more margin, **Indian cross-border collection tools**
  (Razorpay's international/export product, Skydo, Winvesta) are built specifically for Indian
  exporters — they auto-generate eFIRC per transaction and charge roughly 1-3%, but you still
  own GST/tax filing yourself.
- All of the above (fees, availability, onboarding speed) change frequently. Re-verify directly
  with the provider before committing — treat every number above as "roughly correct as of
  when this was written," not a live quote.

**Decision framework to embed in the actual build, not a fixed choice up front:** the
license-token and webhook-handling architecture in Section 6 is identical regardless of which
of these you pick — only the SDK import and the webhook event names change. Build the thin
interface in Section 2.4 so swapping providers later is a config change, not a rewrite.

```
  • The 22 core tools                                 • Plugin/workflow marketplace + payouts
                                                       • Admin analytics dashboard

```

### 2.2 — The Offline License Token

The Enterprise tier's own promise — "air-gapped deployment, no internet required" — forces a
specific design: entitlement must be provable without a network call. The mechanism, identical
in spirit to how JetBrains and Tailscale handle offline-capable licenses:

1. The backend holds an **Ed25519 private key** in a secrets manager. It never leaves the
   backend.
2. At checkout or renewal, the backend signs a small JSON payload (a `LicenseToken`: user_id,
   org_id, tier, seats, feature flags, issued_at, expires_at) with that private key.
3. Every desktop install ships the corresponding **public key**, baked in at build time.
4. The client verifies the signature entirely locally — zero network calls needed to prove
   entitlement on every launch.
5. Online-connected tiers (Free/Pro/Team) get a silent background refresh every few days so
   cancellations propagate quickly. Enterprise/air-gapped installs get a long grace period
   (Section 6.1) plus a manual `nexus license activate <file>` CLI path for updates.

### 2.3 — Backend Stack

Recommendation, not mandate: **FastAPI + PostgreSQL + Redis**, because it shares Pydantic
model definitions with the existing desktop client codebase and the team already knows Python.
A Node/Express + Prisma stack works equally well if that's a better fit for whoever builds the
marketplace frontend — the license token contract in Section 6.1 doesn't care what language
signs it, only that Ed25519 signing/verification is implemented correctly on both ends.

### 2.4 — Payment Provider Decision Matrix

Build `nexus_cloud_backend/billing/provider.py` as a thin interface so this choice is a config
value, not an architectural fork:

| | Stripe (direct) | Paddle / Dodo / Lemon Squeezy (MoR) | Razorpay Intl / Skydo (collection) |
|---|---|---|---|
| Legal seller of record | You | The platform | You |
| Who files sales tax/VAT/GST globally | You | The platform | You |
| Typical fee | ~2.9% + 30¢ | ~4-5% + flat fee | ~1-3% |
| India onboarding (2026) | Invite-only, restricted | Generally self-serve | Self-serve, India-native |
| Generates FIRC/eFIRC | No | N/A (not the collector) | Yes, automatically |
| Best fit here | You already have a US/UK entity | Solo dev, no finance team, want zero tax filing | Solo dev who wants lower fees and will own GST directly |

Pick one to start with — Dodo Payments and Razorpay's international product both explicitly
target India-based solo SaaS founders as of 2026 — implement Section 6.2 against it, and keep
the interface thin enough to add a second provider later for a different region.

## SECTION 3: FOUNDATIONAL LAWS — BILLING (IMMUTABLE)

These sit alongside the ten Foundational Laws in the v4.0 prompt. Every line of billing code
must satisfy all of them simultaneously.

**LAW B1 — NEVER TRUST THE CLIENT FOR ENTITLEMENT.**
Every feature gate re-derives the current tier from the signed `LicenseToken` (Section 6.1) or
a server-side check. The desktop UI's displayed tier is a cache for display purposes only,
never the enforcement point.

**LAW B2 — GRACEFUL ENTITLEMENT DEGRADATION.**
A network hiccup, an expired laptop clock, or a missed webhook must never instantly lock out a
paying customer or delete their data. Every tier has a grace period (`GRACE_PERIOD_DAYS` in
Section 6.1) during which the last-known-good entitlement holds. Synthesized tools, memories,
and workflows are never deleted for a billing lapse — only forward access to tier-gated
features is restricted.

**LAW B3 — WEBHOOK IDEMPOTENCY & SIGNATURE VERIFICATION.**
Every webhook handler verifies the provider's cryptographic signature before parsing the
payload, and dedupes by the provider's event ID before mutating any state. Payment providers
retry aggressively; handlers must be safe to run twice.

**LAW B4 — NO RAW PAYMENT DATA EVER TOUCHES YOUR INFRASTRUCTURE.**
Card numbers, CVVs, and full PANs are only ever handled by the payment provider's hosted
Checkout/Elements. Your database stores customer/subscription IDs, never card data — this
keeps you in the simplest PCI compliance tier (SAQ-A) instead of full PCI-DSS.

**LAW B5 — METERING IS SERVER-AUTHORITATIVE FOR ANYTHING BILLABLE.**
The local free-tier task counter (Section 6.4) is advisory UX only. Anything that actually
affects a bill — overage charges, seat counts, marketplace revenue share — is reconciled
server-side from data the client cannot forge.

**LAW B6 — CANCELLATION IS AS EASY AS SIGNUP.**
Self-serve cancellation via a hosted billing portal, reachable in two clicks from account
settings. No retention gauntlet, no "call to cancel." This is both good practice and, in a
growing number of jurisdictions, a legal requirement.

**LAW B7 — AUDIT EVERY BILLING EVENT.**
Every webhook, license issuance, and entitlement check flows through the existing `@audited`
decorator and `audit_logger` from the v4.0 prompt. Billing disputes need a paper trail as much
as security incidents do.

**LAW B8 — COMPLIANCE CLAIMS MUST BE TRUE WHEN MADE.**
Never state "SOC2 Type II," "ISO 27001," or similar on a pricing page, in a sales deck, or in
a signed enterprise contract until the actual audit report exists and is dated. The v4.0
prompt's own sample enterprise pitch line ("We have a SOC2 Type II report") is aspirational
copy — gate it behind the real completed audit, not behind the marketing calendar.

**LAW B9 — TELEMETRY CONSENT PRECEDES ANALYTICS.**
The free-tier task counter is core product function, not telemetry, and needs no separate
consent. Any usage analytics beyond enforcing that limit follows the opt-in consent flow
already specified in the v4.0 prompt's Section 1.5.

## SECTION 6: MODULE SPECIFICATIONS

### 6.1 — `nexus_billing/license_manager.py` (client-side, full implementation)

```python
"""
nexus_billing/license_manager.py

Offline-first license validation for NEXUS AI.

Design goal: a paying Enterprise customer running fully air-gapped (the Tier 4
promise in the core NEXUS AI prompt) must be able to prove their entitlement
WITHOUT any network call. A Personal Pro / Team customer who is online gets a
periodic silent refresh so cancellations/refunds propagate within days.

Cryptographic model:
  - The billing backend holds an Ed25519 PRIVATE key. Never shipped to any client.
  - The corresponding Ed25519 PUBLIC key is embedded as a constant below and
    shipped inside every desktop install.
  - At checkout/renewal the backend issues a small signed JSON payload (a
    LicenseToken) containing tier, seats, feature flags, issue time, and
    expiry. The client verifies the signature locally.
"""

import json
import base64
from dataclasses import dataclass, asdict
from datetime import datetime, timezone, timedelta
from typing import Optional, List, Literal

from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PublicKey
from cryptography.exceptions import InvalidSignature

from nexus_config.settings import APP_ROOT, get_settings
from nexus_config.audit_logger import get_audit_logger

# ─── PUBLIC KEY (safe to embed — this only lets us VERIFY, never issue) ──────
# Generate the keypair once, server-side only:
#   openssl genpkey -algorithm ed25519 -out license_signing_private.pem
#   openssl pkey -in license_signing_private.pem -pubout -out license_signing_public.pem
# The private key NEVER leaves the billing backend's secrets manager.
NEXUS_LICENSE_PUBLIC_KEY_B64 = "REPLACE_WITH_YOUR_BASE64_ED25519_PUBLIC_KEY"

LICENSE_CACHE_PATH = APP_ROOT / "license.json"

Tier = Literal["free", "personal_pro", "team", "enterprise"]

# LAW B2 — grace period before a lapsed/unreachable license soft-downgrades.
GRACE_PERIOD_DAYS: dict[str, int] = {
    "free": 0,
    "personal_pro": 14,
    "team": 14,
    "enterprise": 90,   # air-gapped: long grace, manual refresh via admin_cli
}


@dataclass
class LicenseToken:
    user_id: str
    org_id: Optional[str]
    tier: Tier
    seats: int
    features: List[str]
    issued_at: str        # ISO 8601
    expires_at: str        # ISO 8601 — subscription period end, not license permanence
    signature: str          # base64 Ed25519 signature over the canonical payload


def _canonical_payload(token: LicenseToken) -> bytes:
    """Deterministic bytes for everything EXCEPT the signature. Field order and
    formatting here must exactly match what the backend signs (Section 6.1's
    counterpart in license_issuer.py)."""
    payload = {
        "user_id": token.user_id,
        "org_id": token.org_id,
        "tier": token.tier,
        "seats": token.seats,
        "features": sorted(token.features),
        "issued_at": token.issued_at,
        "expires_at": token.expires_at,
    }
    return json.dumps(payload, sort_keys=True, separators=(",", ":")).encode("utf-8")


def verify_license_signature(token: LicenseToken) -> bool:
    """Verify the Ed25519 signature entirely offline. No network call.
    Returns False on any malformed input rather than raising — callers must
    treat False as 'fall back to free tier', never crash the app."""
    try:
        public_key = Ed25519PublicKey.from_public_bytes(
            base64.b64decode(NEXUS_LICENSE_PUBLIC_KEY_B64)
        )
        public_key.verify(base64.b64decode(token.signature), _canonical_payload(token))
        return True
    except (InvalidSignature, ValueError, Exception):
        return False


class LicenseManager:
    """Loads, verifies, and caches the active license. Read path is safe from
    any thread; refresh/write happens on the background services thread
    (Thread 3 per the core NEXUS AI Section 2.4 thread plan), never the UI
    thread."""

    def __init__(self):
        self._settings = get_settings()
        self._audit = get_audit_logger()
        self._cached_token: Optional[LicenseToken] = None
        self._load_from_disk()

    def _load_from_disk(self) -> None:
        if not LICENSE_CACHE_PATH.exists():
            return
        try:
            raw = json.loads(LICENSE_CACHE_PATH.read_text(encoding="utf-8"))
            token = LicenseToken(**raw)
            if verify_license_signature(token):
                self._cached_token = token
            else:
                self._audit.log(
                    event_type="SECURITY_REJECT",
                    data={"reason": "license_signature_invalid"},
                    module="nexus_billing.license_manager",
                    function_name="_load_from_disk",
                    success=False,
                )
        except Exception as exc:
            self._audit.log(
                event_type="SYSTEM_ERROR",
                data={"reason": "license_load_failed", "error": str(exc)},
                module="nexus_billing.license_manager",
                function_name="_load_from_disk",
                success=False,
            )

    def install_token(self, raw_token_json: str) -> bool:
        """Called by the onboarding wizard or `nexus license activate <file>`.
        Validates BEFORE writing to disk — never persist an unverifiable token."""
        try:
            token = LicenseToken(**json.loads(raw_token_json))
        except Exception:
            return False

        if not verify_license_signature(token):
            self._audit.log(
                event_type="SECURITY_REJECT",
                data={"reason": "license_install_signature_invalid"},
                module="nexus_billing.license_manager",
                function_name="install_token",
                success=False,
            )
            return False

        LICENSE_CACHE_PATH.write_text(json.dumps(asdict(token)), encoding="utf-8")
        self._cached_token = token
        self._audit.log(
            event_type="CONFIG_CHANGE",
            data={"tier": token.tier, "org_id": token.org_id},
            module="nexus_billing.license_manager",
            function_name="install_token",
            success=True,
        )
        return True

    def current_tier(self) -> Tier:
        """The single source of truth every tool-gate and UI feature flag
        must call. NEVER read settings.TIER directly for entitlement
        decisions — that field is a display cache, not the trust boundary
        (LAW B1)."""
        if self._cached_token is None:
            return "free"

        expires_at = datetime.fromisoformat(self._cached_token.expires_at)
        grace_days = GRACE_PERIOD_DAYS.get(self._cached_token.tier, 0)
        hard_cutoff = expires_at + timedelta(days=grace_days)

        if datetime.now(timezone.utc) > hard_cutoff:
            # Past subscription end AND past grace period: soft-downgrade.
            # Never delete synthesized tools, memory, or workflows (LAW B2) —
            # only gate tier-restricted features going forward.
            return "free"

        return self._cached_token.tier

    def has_feature(self, feature_name: str) -> bool:
        if self._cached_token is None:
            return False
        return feature_name in self._cached_token.features

    def days_until_hard_cutoff(self) -> Optional[int]:
        """Used by the HUD to show a friendly 'renew within N days' banner."""
        if self._cached_token is None:
            return None
        expires_at = datetime.fromisoformat(self._cached_token.expires_at)
        grace_days = GRACE_PERIOD_DAYS.get(self._cached_token.tier, 0)
        remaining = (expires_at + timedelta(days=grace_days) - datetime.now(timezone.utc)).days
        return max(remaining, 0)


_manager: Optional[LicenseManager] = None


def get_license_manager() -> LicenseManager:
    global _manager
    if _manager is None:
        _manager = LicenseManager()
    return _manager
```

### 6.2 — `nexus_cloud_backend/billing/stripe_webhooks.py` (full implementation)

The same verify-signature → dedupe-by-event-id → update-state → issue-or-revoke-token pattern
applies identically to Paddle/Dodo — only the SDK calls and event names change.

```python
"""
nexus_cloud_backend/billing/stripe_webhooks.py

Receives and processes Stripe subscription lifecycle events, then issues or
lets lapse a signed LicenseToken (nexus_billing/license_manager.py on the
client) for the affected user.

LAW B3: every handler verifies the Stripe signature AND dedupes by event.id
before touching the database. Stripe retries webhooks aggressively (up to
3 days) on any non-2xx response, so this MUST be idempotent.
"""

import os
from datetime import datetime, timezone

import stripe
from fastapi import APIRouter, Request, HTTPException, Depends
from sqlalchemy.orm import Session

from ..db.models import ProcessedWebhookEvent, Subscription, User
from .license_issuer import issue_license_token

router = APIRouter(prefix="/webhooks", tags=["billing"])

STRIPE_WEBHOOK_SECRET = os.environ["STRIPE_WEBHOOK_SECRET"]   # from the Stripe dashboard, per endpoint
stripe.api_key = os.environ["STRIPE_SECRET_KEY"]              # secrets manager only, never hardcoded

# Maps Stripe Price IDs to NEXUS AI tiers. Keep in sync with your Stripe
# product catalog. Never infer tier from the price amount — prices change.
PRICE_ID_TO_TIER = {
    os.environ["STRIPE_PRICE_PERSONAL_PRO_MONTHLY"]: "personal_pro",
    os.environ["STRIPE_PRICE_PERSONAL_PRO_ANNUAL"]: "personal_pro",
    os.environ["STRIPE_PRICE_TEAM_MONTHLY"]: "team",
    os.environ["STRIPE_PRICE_ENTERPRISE_ANNUAL"]: "enterprise",
}


@router.post("/stripe")
async def handle_stripe_webhook(request: Request, db: Session = Depends(get_db)):
    payload = await request.body()
    sig_header = request.headers.get("stripe-signature", "")

    try:
        event = stripe.Webhook.construct_event(payload, sig_header, STRIPE_WEBHOOK_SECRET)
    except (ValueError, stripe.error.SignatureVerificationError):
        raise HTTPException(status_code=400, detail="Invalid signature")

    # Idempotency (LAW B3): Stripe event IDs are globally unique and stable
    # across retries. If we've already recorded this one, ack and stop.
    if db.query(ProcessedWebhookEvent).filter_by(event_id=event["id"]).first():
        return {"status": "already_processed"}

    event_type = event["type"]
    data_object = event["data"]["object"]

    if event_type == "checkout.session.completed":
        _handle_checkout_completed(db, data_object)
    elif event_type == "customer.subscription.updated":
        _handle_subscription_updated(db, data_object)
    elif event_type == "customer.subscription.deleted":
        _handle_subscription_canceled(db, data_object)
    elif event_type == "invoice.payment_failed":
        _handle_payment_failed(db, data_object)

    # Record AFTER successful processing so a crash mid-handler causes a
    # safe retry (Stripe resends) rather than a silently dropped event.
    db.add(ProcessedWebhookEvent(
        event_id=event["id"], event_type=event_type,
        processed_at=datetime.now(timezone.utc),
    ))
    db.commit()
    return {"status": "ok"}


def _handle_checkout_completed(db: Session, session: dict) -> None:
    user = db.query(User).filter_by(provider_customer_id=session["customer"]).first()
    if not user:
        return

    stripe_sub = stripe.Subscription.retrieve(session["subscription"])
    price_id = stripe_sub["items"]["data"][0]["price"]["id"]
    tier = PRICE_ID_TO_TIER.get(price_id, "free")
    period_end = datetime.fromtimestamp(stripe_sub["current_period_end"], tz=timezone.utc)

    db.add(Subscription(
        user_id=user.id, provider="stripe",
        provider_subscription_id=session["subscription"],
        tier=tier, status="active", current_period_end=period_end,
    ))
    db.commit()
    issue_license_token(user_id=user.id, org_id=user.org_id, tier=tier, expires_at=period_end)


def _handle_subscription_updated(db: Session, stripe_sub: dict) -> None:
    sub = db.query(Subscription).filter_by(provider_subscription_id=stripe_sub["id"]).first()
    if not sub:
        return
    price_id = stripe_sub["items"]["data"][0]["price"]["id"]
    sub.tier = PRICE_ID_TO_TIER.get(price_id, sub.tier)
    sub.status = stripe_sub["status"]
    sub.current_period_end = datetime.fromtimestamp(stripe_sub["current_period_end"], tz=timezone.utc)
    db.commit()

    if stripe_sub["status"] in ("active", "trialing"):
        user = db.query(User).filter_by(id=sub.user_id).first()
        issue_license_token(user_id=sub.user_id, org_id=user.org_id if user else None,
                             tier=sub.tier, expires_at=sub.current_period_end)


def _handle_subscription_canceled(db: Session, stripe_sub: dict) -> None:
    sub = db.query(Subscription).filter_by(provider_subscription_id=stripe_sub["id"]).first()
    if not sub:
        return
    sub.status = "canceled"
    db.commit()
    # LAW B2: don't revoke immediately. Let the already-issued token run to
    # its natural expires_at + grace period. Cancellation is not an instant lockout.


def _handle_payment_failed(db: Session, invoice: dict) -> None:
    # Stripe's Smart Retries re-attempt automatically (dunning). We simply
    # don't issue a new token on failure — the existing one runs out
    # naturally, and the grace period gives the customer time to update
    # their card before anything actually degrades.
    pass
```

### 6.3 — Tier gating in `nexus_tools/registry.py`

```python
"""
Addition to nexus_tools/registry.py — gate tools behind subscription tiers.

Usage:
    @requires_tier("personal_pro")
    @tool
    def sync_memory_to_cloud(...) -> str:
        ...
"""

import json
from functools import wraps

from nexus_billing.license_manager import get_license_manager

TIER_RANK = {"free": 0, "personal_pro": 1, "team": 2, "enterprise": 3}


def requires_tier(minimum_tier: str):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            current = get_license_manager().current_tier()
            if TIER_RANK[current] < TIER_RANK[minimum_tier]:
                # Matches the plugin JSON contract from v4.0 LAW 5:
                # {"success": bool, "result": any, "error": str|null}
                return json.dumps({
                    "success": False,
                    "result": None,
                    "error": (
                        f"This capability requires {minimum_tier.replace('_', ' ').title()} "
                        f"or higher. You're currently on {current.replace('_', ' ').title()}. "
                        f"Upgrade at https://nexus-ai.dev/upgrade"
                    ),
                })
            return func(*args, **kwargs)
        return wrapper
    return decorator
```

### 6.4 — `nexus_billing/usage_metering.py` (full implementation)

```python
"""
nexus_billing/usage_metering.py

Free-tier task counter. Per LAW B5, this LOCAL count is advisory/UX only —
it lets a free-tier user see "72 / 100 tasks used this month" with zero
network latency. Anything that actually affects billing is reconciled
server-side, never trusted from this file alone, since a modified client
could report anything.
"""

import json
from dataclasses import dataclass, asdict
from datetime import datetime, timezone

from nexus_config.settings import APP_ROOT

USAGE_PATH = APP_ROOT / "usage_counter.json"
FREE_TIER_MONTHLY_LIMIT = 100


@dataclass
class UsageCounter:
    month_key: str       # "2026-07"
    tasks_completed: int


def _current_month_key() -> str:
    now = datetime.now(timezone.utc)
    return f"{now.year:04d}-{now.month:02d}"


def _load() -> UsageCounter:
    if USAGE_PATH.exists():
        try:
            data = json.loads(USAGE_PATH.read_text(encoding="utf-8"))
            counter = UsageCounter(**data)
            if counter.month_key == _current_month_key():
                return counter
        except Exception:
            pass
    return UsageCounter(month_key=_current_month_key(), tasks_completed=0)


def _save(counter: UsageCounter) -> None:
    # Atomic write — matches the Section 2.5 atomic-rename pattern from the
    # core NEXUS AI prompt. Never corrupt this file mid-task.
    tmp_path = USAGE_PATH.with_suffix(".tmp")
    tmp_path.write_text(json.dumps(asdict(counter)), encoding="utf-8")
    tmp_path.replace(USAGE_PATH)


def increment_and_check(tier: str) -> tuple[bool, int, int]:
    """Call once per completed agent task, in the orchestrator's final graph
    node alongside the existing memory_write step.

    Returns: (allowed, used, limit). limit is -1 for unlimited tiers."""
    if tier != "free":
        return True, 0, -1

    counter = _load()
    if counter.tasks_completed >= FREE_TIER_MONTHLY_LIMIT:
        return False, counter.tasks_completed, FREE_TIER_MONTHLY_LIMIT

    counter.tasks_completed += 1
    _save(counter)
    return True, counter.tasks_completed, FREE_TIER_MONTHLY_LIMIT
```

## SECTION 7: MARKETPLACE PAYOUTS

The Plugin Marketplace (30% rev-share) and Workflow Marketplace (20% rev-share) both need a
split-payment mechanism so a developer gets paid without you ever custodying their money
longer than necessary:

- **If billing runs on Stripe:** use **Stripe Connect (Express accounts)**. Each plugin/workflow
  developer completes a lightweight Connect onboarding; sales route through
  `stripe.PaymentIntent` with `application_fee_amount` set to your rev-share cut, and the
  remainder transfers automatically to the developer's connected account.
- **If billing runs on a Merchant of Record:** most MoRs (Paddle, Dodo) offer an equivalent
  split-payout or affiliate/reseller mechanism — check the specific provider's docs, since this
  is the one area where MoR feature parity with Stripe Connect varies the most.
- Either way: `PluginListing.payout_account_id` / `WorkflowListing.payout_account_id` (Section 5)
  is deliberately provider-agnostic so the marketplace tables don't need to change if the
  payout mechanism changes later.
- **Never hold marketplace funds longer than the provider's standard settlement window.**
  Sitting on developer payouts to "smooth cash flow" is both a trust-destroying practice for
  your developer ecosystem (the exact moat the v4.0 prompt's Section 1.6 describes) and, past
  a certain volume, can trigger money-transmitter licensing obligations in some jurisdictions —
  another item for the lawyer conversation in Section 1.4.
